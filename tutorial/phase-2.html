Connecting to Grok

Grok's API speaks the same shape as OpenAI's chat API. We use the official openai npm package and point it at xAI's URL.

Step 1: Store your API key

Create a .env file at the project root (same level as package.json). Add it to .gitignore so it never gets committed.

.env
XAI_API_KEY=your_key_here

Environment variable

Never paste API keys into source files.

Line 1XAI_API_KEY=...

dotenv (loaded in the next file) reads this and sets process.env.XAI_API_KEY. Replace your_key_here with your real key from xAI's developer portal.

Why: Secrets in code end up in git history forever. Environment variables stay on your machine.

Step 2: Create the Grok agent wrapper

Create src/harness/agent.ts. This class is a thin bridge between your harness and the model.

src/harness/agent.ts
import OpenAI from 'openai';
import dotenv from 'dotenv';

dotenv.config();

export class GrokAgent {
  private client: OpenAI;
  public model = 'grok-4.3';

  constructor() {
    this.client = new OpenAI({
      apiKey: process.env.XAI_API_KEY,
      baseURL: 'https://api.x.ai/v1',
    });
  }

  async chat(messages: any[], tools: any[] = []) {
    const response = await this.client.chat.completions.create({
      model: this.model,
      messages,
      temperature: 0.7,
      ...(tools.length > 0 ? { tools, tool_choice: 'auto' as const } : {}),
    });
    return response;
  }
}

Talking to the model

Each method here will be called from the agent loop in Phase 4.

Line 1import OpenAI

The OpenAI SDK — also works for Grok because xAI copied the same request/response format.

Lines 2–4Load environment variables

dotenv.config() runs once when this module loads. It reads .env and populates process.env before the constructor reads the API key.

Why at top level: The key must exist before new OpenAI({ apiKey: ... }) runs.
Lines 6–8Class shell & model name

GrokAgent is your harness's name for "the thing that calls the brain." private client hides the SDK instance — outside code calls chat(), not the raw client. model is public so you can change or log it easily.

Lines 10–15Configure the client

apiKey — from environment, never hard-coded. baseURL: 'https://api.x.ai/v1' — the only difference from a vanilla OpenAI setup; sends requests to Grok instead of OpenAI.

Why a wrapper class: Later you can swap models, add retries, or log token usage in one place.
Line 17chat() parameters

messages — the conversation history from your Session. tools defaults to [] for plain chat without tool calling (Phase 3 adds tools).

Lines 18–23The API call

model — which Grok version to use. messages — full history the model sees. temperature: 0.7 — some creativity, not totally random.

The spread ...(tools.length > 0 ? { tools, tool_choice: 'auto' } : {}) only adds tools when you actually have tools. With exactOptionalPropertyTypes, passing tools: undefined would fail — omitting the property entirely is correct.

tool_choice: 'auto' as const — tells TypeScript this is the literal string 'auto', not just any string. The model decides whether to call tools or reply in text.

Lines 24–25return response

Returns the full SDK response object. The agent loop (Phase 4) will read response.choices[0].message to see if the model wants to use tools or finished with text.
