06

Safety, Permissions & Agent Profiles

💡
How to use this lesson: Phases 1–5 gave you memory, tools, a loop, and snapshots. Phase 6 adds modes — the harness decides which tools exist and which system instructions apply. You will create profiles.ts, tighten tools.ts and loop.ts, and pick a profile from the terminal. Same sidebar pattern as before.

So far, one prompt told the model “be careful.” That is a guide (feedforward). Guides help, but models drift — especially under pressure. A real harness also installs sensors: code that blocks illegal actions even when the model insists.

This phase introduces agent profiles: named bundles of systemPrompt + allowedTools. Three built-in profiles:

  • Planner — read-only exploration; outputs a plan, cannot write files.
  • Implementer — full file tools; the default “build it” mode from earlier phases.
  • Reviewer — read-only; structured feedback in the final answer, no edits.
Two enforcement layers (both required):
  1. Schema layer — pass only allowed tool definitions into agent.chat(). If write_file is not in the list, the model should not receive it as an option.
  2. Execution layer — in executeTool(), refuse to run a tool that is not allowed, and return a clear error string as the tool result. This catches hallucinated tool names or resumed sessions where history mentions tools that are no longer allowed.

OpenCode’s permission rulesets do more (ask/deny/merge, per-path patterns). You are learning the core idea: the harness enforces boundaries, not the model.

Prerequisites: Phase 5 complete — toApiMessages filters hidden messages, recordTurnSnapshot runs before each chat(). You will add src/harness/profiles.ts and edit tools.ts, loop.ts, and main.ts.

Step 1: Create src/harness/profiles.ts

Profiles are data, not magic. Each profile is a small object your loop and CLI can pass around.

src/harness/profiles.ts — type & registry
export type AgentProfile = {
  id: string;
  label: string;
  systemPrompt: string;
  allowedTools: string[];
};

export type ProfileId = 'planner' | 'implementer' | 'reviewer';

export const PROFILES: Record<ProfileId, AgentProfile> = {
  planner: {
    id: 'planner',
    label: 'Planner (read-only)',
    systemPrompt:
      'You are in PLANNER mode. Use list_files and read_file to explore. ' +
      'Do not claim you edited or wrote files. Output a numbered plan the user can approve. Be concise.',
    allowedTools: ['read_file', 'list_files'],
  },
  implementer: {
    id: 'implementer',
    label: 'Implementer (read + write)',
    systemPrompt:
      'You are in IMPLEMENTER mode. Explore with list_files and read_file before editing. ' +
      'Use write_file for changes. Summarize what you changed and how the user can verify (e.g. run tests).',
    allowedTools: ['read_file', 'write_file', 'list_files'],
  },
  reviewer: {
    id: 'reviewer',
    label: 'Reviewer (read-only feedback)',
    systemPrompt:
      'You are in REVIEWER mode. Read and list files only — never write. ' +
      'Reply with structured feedback: brief summary, issues by severity (high/medium/low), and suggested fixes.',
    allowedTools: ['read_file', 'list_files'],
  },
};

export const DEFAULT_PROFILE_ID: ProfileId = 'implementer';

Add helpers below the registry in the same file:

src/harness/profiles.ts — resolve & lookup
export function getProfile(id: ProfileId): AgentProfile {
  return PROFILES[id];
}

export function resolveProfileId(raw?: string): ProfileId {
  const key = (raw ?? DEFAULT_PROFILE_ID).trim().toLowerCase();
  if (key in PROFILES) {
    return key as ProfileId;
  }
  const choices = Object.keys(PROFILES).join(', ');
  throw new Error(`Unknown profile "${raw}". Choose: ${choices}`);
}

Step 2: Filter schemas and guard execution in tools.ts

Open src/harness/tools.ts. Keep TOOLS as the full catalog. Add functions that slice it per profile and block disallowed runs.

export function getToolSchemas(allowedTools: string[]) {
  const allowed = new Set(allowedTools);
  return TOOLS.filter((t) => allowed.has(t.function.name));
}

export function isToolAllowed(name: string, allowedTools: string[]): boolean {
  return allowedTools.includes(name);
}

src/harness/tools.ts — executeTool signature & guard
export async function executeTool(
  name: string,
  argsJson: string,
  allowedTools: string[],
): Promise<string> {
  if (!isToolAllowed(name, allowedTools)) {
    return (
      `Permission denied: profile does not allow "${name}". ` +
      `Allowed tools: ${allowedTools.join(', ')}`
    );
  }

  let args: Record<string, unknown>;
  try {
    args = JSON.parse(argsJson);
  } catch {
    return `Invalid tool arguments JSON: ${argsJson}`;
  }

  // … existing switch (read_file, write_file, list_files) unchanged …
}

Lines 1–12Permission check first

The model sees this text as a normal tool result on the next turn — same pattern as sandbox errors in Phase 3. It can adjust (e.g. stop trying write_file in planner mode).

Why: Phase 7 will log denials; for now the message is enough proof the harness blocked the call.

3b — snapshots include profile. Update TurnSnapshot and recordTurnSnapshot from Phase 5:

src/harness/loop.ts — snapshot with profileId
type TurnSnapshot = {
  step: number;
  profileId: string;
  messageCount: number;
  toolsAvailable: string[];
  workingDir: string;
  timestamp: string;
};

async function recordTurnSnapshot(
  session: Session,
  step: number,
  profile: AgentProfile,
): Promise<void> {
  const toolSchemas = getToolSchemas(profile.allowedTools);
  const snapshot: TurnSnapshot = {
    step,
    profileId: profile.id,
    messageCount: session.getHistory().length,
    toolsAvailable: toolSchemas.map((t) => t.function.name),
    workingDir: process.cwd(),
    timestamp: new Date().toISOString(),
  };

  await session.addMessage(
    'system',
    `TURN SNAPSHOT: ${JSON.stringify(snapshot)}`,
    { hidden: true },
  );
}

Snapshots match reality

Lines 15–16Filtered tool names

3c — runTurn takes a profile. Add a fourth parameter and use it inside the loop:

src/harness/loop.ts — runTurn signature & loop body (key lines)
export async function runTurn(
  session: Session,
  agent: GrokAgent,
  userInput: string,
  profile: AgentProfile,
): Promise<string> {
  const toolSchemas = getToolSchemas(profile.allowedTools);

  await session.addMessage('user', userInput);

  for (let step = 0; step < MAX_ITERATIONS; step++) {
    await recordTurnSnapshot(session, step, profile);

    const response = await agent.chat(
      toApiMessages(session.getHistory()),
      toolSchemas,
    );
    const message = response.choices[0]?.message;

    if (!message) {
      throw new Error('Model returned no message');
    }

    const toolCalls = message.tool_calls ?? [];

    if (toolCalls.length > 0) {
      await session.addMessage('assistant', message.content ?? '', {
        tool_calls: toolCalls,
      });

      for (const toolCall of toolCalls) {
        if (toolCall.type !== 'function') continue;
        const fn = toolCall.function;
        console.log(`  tool → ${fn.name}`);
        const result = await executeTool(
          fn.name,
          fn.arguments,
          profile.allowedTools,
        );
        await session.addMessage('tool', result, {
          tool_call_id: toolCall.id,
          name: fn.name,
        });
      }
      continue;
    }

    const text = message.content ?? '';
    await session.addMessage('assistant', text);
    return text;
  }

  throw new Error(`Agent loop exceeded ${MAX_ITERATIONS} iterations`);
}

Step 4: Pick a profile in main.ts

Replace the hard-coded SYSTEM_PROMPT with the active profile’s prompt. Read the profile from an environment variable so you can switch modes without editing code.

src/main.ts — profile-aware CLI
import readline from 'readline/promises';
import { stdin as input, stdout as output } from 'process';
import { GrokAgent } from './harness/agent.js';
import { Session } from './harness/session.js';
import { runTurn } from './harness/loop.js';
import { resolveProfileId, getProfile } from './harness/profiles.js';

async function main() {
  const profileId = resolveProfileId(process.env.AGENT_PROFILE);
  const profile = getProfile(profileId);

  const session = new Session();
  await session.load();
  const agent = new GrokAgent();

  if (session.getHistory().length === 0) {
    await session.addMessage('system', profile.systemPrompt);
  }

  console.log(`Session ${session.id}`);
  console.log(`Profile: ${profile.label}`);
  console.log(`Allowed tools: ${profile.allowedTools.join(', ')}`);
  console.log('Empty line to quit\n');

  const rl = readline.createInterface({ input, output });

  while (true) {
    const line = await rl.question('> ');
    if (!line.trim()) break;

    console.log('\n… agent working …\n');
    try {
      const reply = await runTurn(session, agent, line, profile);
      console.log(`\n${reply}\n`);
    } catch (err) {
      console.error(err);
    }
  }

  rl.close();
}

main().catch(console.error);

tscTroubleshooting
  • Expected 3 arguments, but got 2 — every executeTool call needs profile.allowedTools (or an explicit array in smoke tests).
  • Planner still writes files — check you pass toolSchemas to chat(), not full TOOLS.
  • Wrong prompt after switching profile — old session still has the previous system message; start a new session file.
  • Unknown profile error — typo in AGENT_PROFILE; must be planner, implementer, or reviewer.

What you are not building yet (on purpose):
  • Interactive “ask before write” — OpenCode pauses and waits for human approval. You hard-deny or hard-allow per profile instead.
  • Per-path rules — e.g. “allow edits only under src/”. Phase 3’s workspace sandbox is still your path safety net.
  • Separate models per profile — same Grok model for all three; only tools and prompts differ.
  • Automated test runner — implementer prompt suggests verification; Phase 8 points to real CI hooks.
