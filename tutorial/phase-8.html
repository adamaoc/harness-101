Next Steps & Advanced Patterns

🎓
How to use this lesson: Phases 1–7 built a real harness — memory, Grok, tools, loop, snapshots, profiles, logs. Phase 8 is the capstone: you wire a few patterns production harnesses use (plan → build → review, diff preview, compaction, lightweight sub-agents). Each step says which file to open and where to paste or replace code. Go in order; skip a pattern only if you understand what you are deferring.

You are not starting over. You are bolting new abilities onto the same project you have been typing since Phase 1. Think of your harness as a small robot:

  • Brain — Grok (Phase 2)
  • Memory — sessions/*.jsonl (Phase 1)
  • Hands — file tools (Phase 3)
  • Reflexes — the loop (Phase 4)
  • Notes to self — turn snapshots (Phase 5)
  • Rules — profiles (Phase 6)
  • Eyes — logs/*.jsonl (Phase 7)

Phase 8 teaches the harness how to work in stages, show diffs before it hurts, forget old chat safely, and ask a helper agent for one job.

What “advanced” means here

We are not cloning any single product. We are adding small, understandable hooks inspired by patterns seen in tools like OpenCode and Cursor, so names like compaction and subagents feel familiar when you read other harness writeups later.

Prerequisites: Phase 7 complete — HarnessLogger wired through main.ts and loop.ts, logs/ in .gitignore. Your agent should run with npm start and finish at least one tool-using turn.

Step 2: Multi-phase workflow (Plan → Implement → Review)

You already have three profiles from Phase 6. Phase 8’s first pattern is not new code — it is how you run them in sequence like a tiny software team.

  1. Plan (read-only)
    AGENT_PROFILE=planner npm start
    Ask: “Explore src/harness/ and propose how to add diff preview to write_file.”
    Copy the numbered plan from the assistant message. Quit with an empty line.
  2. Implement (read + write)
    Start a new session (delete or rename old sessions/*.jsonl if you want a clean slate) or continue — your choice.
    AGENT_PROFILE=implementer npm start
    Paste: “Follow this plan: …” and let it edit files.
  3. Review (read-only feedback)
    AGENT_PROFILE=reviewer npm start
    Ask: “Review the diff-preview changes for bugs and missing edge cases.”

Why this matters: Production harnesses (OpenCode’s plan vs build agents) separate thinking from editing so the model does not “helpfully” rewrite half your repo while still exploring. Your profiles are the beginner version of that idea.

Optional later: A single CLI command that runs planner → implementer → reviewer automatically. That needs orchestration code (Phase 8 Step 5’s sub-agent pattern is one building block). For now, you are the orchestrator — and that is enough to learn the workflow.

Step 3: Diff preview before writes

When the model calls write_file, blind overwrites are scary. A diff is a text report of what changed: lines removed (-) and lines added (+). We will:

  1. Install a tiny diff library.
  2. Add src/harness/diff.ts to format patches.
  3. Change write_file in src/harness/tools.ts to include the patch in the tool result (so the model — and your logs — see what happened).

3b — Create src/harness/diff.ts (new file)

src/harness/diff.ts — new file
import { createTwoFilesPatch } from 'diff';

const MAX_DIFF_CHARS = 4000;

/** Unified diff string for logging and tool results. */
export function formatFileDiff(
  relativePath: string,
  before: string,
  after: string,
): string {
  const patch = createTwoFilesPatch(
    relativePath,
    relativePath,
    before,
    after,
    'before',
    'after',
  );

  if (patch.length <= MAX_DIFF_CHARS) {
    return patch;
  }

  return (
    patch.slice(0, MAX_DIFF_CHARS) +
    `\n… (diff truncated at ${MAX_DIFF_CHARS} characters)`
  );
}

Human-readable patches

Same format git diff uses.

Lines 1–3MAX_DIFF_CHARS

A huge file could produce a megabyte diff and blow up the model context. Truncation is a harness safety rail — not laziness.

Lines 5–18createTwoFilesPatch

Compares old vs new full file text. New files get “all lines added” style output — still useful.

async function writeFile(pathArg: string, content: string): Promise<string> {
  const filePath = resolvePath(pathArg);

  let before = '';
  try {
    before = await fs.readFile(filePath, 'utf-8');
  } catch {
    // new file — before stays ''
  }

  await fs.mkdir(path.dirname(filePath), { recursive: true });
  await fs.writeFile(filePath, content, 'utf-8');

  const patch = formatFileDiff(pathArg, before, content);

  return (
    `Wrote ${pathArg} (${content.length} characters)\n\n` +
    `--- diff ---\n${patch}`
  );
}

Sensor, not gate

This version still writes immediately — it only reports the diff.

Lines 1–10Read before write

If the file did not exist, before is empty — the patch shows a full new file. If read fails for another reason, the harness still throws from resolvePath / write — same as before.

Lines 15–22Return value

The model sees the diff in the tool result on the next loop step. Phase 7’s preview() in logs may truncate it — that is OK; the session JSONL still has the full tool message for replay.

Stricter harness (later): Two-step propose_edit + human approval before apply_edit. Diff preview is the gentle first step.

Step 4: Context compaction (summarize old chat)

Long sessions fill the model’s context window (how much text it can see at once). Symptoms from Phase 7 logs: totalTokens climbing every turn, slower replies, or the API erroring on “context length exceeded.”

Compaction means: replace a chunk of old messages with a short summary the model still reads, and hide the originals so toApiMessages does not send them.

4a — Teach the session to hide messages — src/harness/session.ts

At the bottom of the Session class (before the closing } of the class), add two methods:

src/harness/session.ts — append inside class Session
  /** Mark messages hidden so toApiMessages skips them (Phase 8 compaction). */
  markHidden(startIndex: number, endIndex: number): void {
    for (let i = startIndex; i <= endIndex; i++) {
      if (this.messages[i]) {
        this.messages[i].hidden = true;
      }
    }
  }

  /** Rewrite JSONL after compaction so hidden flags survive restart. */
  async rewriteDisk(): Promise<void> {
    await fs.mkdir(path.dirname(this.filePath), { recursive: true });
    const body = this.messages.map((m) => JSON.stringify(m)).join('\n');
    await fs.writeFile(this.filePath, body ? body + '\n' : '', 'utf-8');
  }
markHiddenReuse Phase 5 flag

Phase 5’s hidden: true on snapshots already kept clutter out of the API. Compaction uses the same mechanism for old user/assistant/tool turns.

rewriteDiskDurability

Without this, restarting the CLI would reload old messages from JSONL and undo compaction. Rewriting the file is blunt but easy to understand.

4b — Create src/harness/compaction.ts (new file)

src/harness/compaction.ts — new file
import type { Session } from './session.js';
import type { GrokAgent } from './agent.js';
import type { HarnessLogger } from './logger.js';

/** When visible messages exceed this, compact the middle. */
const COMPACT_WHEN_VISIBLE_OVER = 30;

/** Keep this many newest visible messages after compacting. */
const KEEP_RECENT_VISIBLE = 12;

export async function maybeCompact(
  session: Session,
  agent: GrokAgent,
  logger: HarnessLogger,
): Promise<void> {
  const visible = session.getHistory().filter((m) => !m.hidden);

  if (visible.length <= COMPACT_WHEN_VISIBLE_OVER) {
    return;
  }

  // Keep first visible message (usually system) + recent tail; summarize the middle.
  const middle = visible.slice(1, visible.length - KEEP_RECENT_VISIBLE);

  if (middle.length === 0) {
    return;
  }

  const transcript = middle
    .map((m) => `[${m.role}] ${m.content}`.slice(0, 500))
    .join('\n');

  const summarizePrompt =
    'Summarize this agent conversation for future turns. ' +
    'Keep: user goals, files touched, decisions, errors, open tasks. ' +
    'Drop: pleasantries and repeated tool output. Under 400 words.\n\n' +
    transcript;

  const started = Date.now();
  const response = await agent.chat(
    [{ role: 'user', content: summarizePrompt }],
    [],
  );
  const summary = response.choices[0]?.message?.content?.trim() ?? '(empty summary)';

  await logger.event('compaction', {
    hiddenCount: middle.length,
    keptRecent: KEEP_RECENT_VISIBLE,
    durationMs: Date.now() - started,
    summaryChars: summary.length,
  });

  // Hide middle messages in the full history array (match by reference).
  const history = session.getHistory();
  for (const msg of middle) {
    const idx = history.indexOf(msg);
    if (idx >= 0) {
      session.markHidden(idx, idx);
    }
  }

  await session.addMessage(
    'system',
    `COMPACTED HISTORY (${middle.length} messages summarized):\n${summary}`,
    { hidden: false },
  );

  await session.rewriteDisk();
}

Cheaper than sending everything

One extra model call when the session gets long.

ThresholdsTunable knobs

Start with 30 / 12. If you still hit context errors, lower COMPACT_WHEN_VISIBLE_OVER. If summaries feel lossy, raise KEEP_RECENT_VISIBLE.

Summarize callSeparate mini-turn

We pass a one-off user message — not the full session — so the summarizer is not confused by tool schemas. Production harnesses often use a cheaper or smaller model here; you can add that when you support multiple models.

compaction eventObservability

Grep logs/*.jsonl for "kind":"compaction" to see when summaries ran and how big they were.

Step 5: Lightweight sub-agents (delegate one task)

A sub-agent is a separate brain with its own short memory, given one job, then returns an answer to the main agent. OpenCode runs them as child sessions; Hermes caps recursion depth. Your version stays small:

  • New session ID (child does not pollute parent transcript).
  • Fixed profile (e.g. reviewer or planner).
  • One user message, one runTurn, return text.

5a — Create src/harness/subagent.ts (new file)

src/harness/subagent.ts — new file
import { Session } from './session.js';
import { GrokAgent } from './agent.js';
import { runTurn } from './loop.js';
import { getProfile, type ProfileId } from './profiles.js';
import { HarnessLogger } from './logger.js';

export type DelegateResult = {
  childSessionId: string;
  profileId: ProfileId;
  reply: string;
};

/**
 * Run one turn in a fresh session — used by the parent agent's delegate tool.
 */
export async function runSubagentTurn(
  task: string,
  profileId: ProfileId,
  parentSessionId: string,
): Promise<DelegateResult> {
  const profile = getProfile(profileId);
  const session = new Session();
  await session.load();

  await session.addMessage('system', profile.systemPrompt);
  await session.addMessage(
    'system',
    `You are a sub-agent spawned by parent session ${parentSessionId}. ` +
      'Complete only the task below, then stop.',
    { hidden: true },
  );

  const agent = new GrokAgent();
  const logger = new HarnessLogger(session.id);

  const reply = await runTurn(session, agent, task, profile, logger);

  return {
    childSessionId: session.id,
    profileId,
    reply,
  };
}

Parent history stays smaller; you can open sessions/<child-id>.jsonl to debug what the helper did.
