The first thing we build is the most important part of any harness: durable state — a way to remember every message even if the process crashes.

Step 1: Create the Project

Run these commands in your terminal. Each one sets up one piece of the project.

Terminal
mkdir my-ts-agent && cd my-ts-agent
npm init -y
npm install openai dotenv
npm install -D typescript ts-node @types/node
npx tsc --init

What each command does

Run these top to bottom in an empty folder.

Line 1Create and enter the project folder

mkdir my-ts-agent creates a new directory. && means "and then, if that succeeded." cd my-ts-agent moves you inside it so every file you create lands in the right place.

Why: Keeping the harness in its own folder avoids mixing it with other projects and makes paths predictable.
Line 2Initialize npm

npm init -y creates a package.json file. The -y flag accepts all defaults so you aren't prompted with questions.

Why: package.json is how Node knows your project name, dependencies, and how to run scripts.
Line 3Install runtime packages

openai is the SDK we use to talk to Grok (xAI's API is OpenAI-compatible). dotenv loads secrets like your API key from a .env file so they never go in source code.

Why: These run when your agent runs — they're "production" dependencies, not just for development.
Line 4Install dev-only packages

-D saves packages as devDependencies. typescript compiles TS to JS. ts-node lets you run TS directly while learning. @types/node teaches TypeScript about Node globals like fs and process.

Why: Without @types/node, your editor will show red squiggles on every Node import even when the code works.
Line 5Generate TypeScript config

npx tsc --init creates tsconfig.json — the rulebook TypeScript follows when checking and compiling your code.

Why: We'll tweak this file in the next step so Node and strict typing work together.

Step 2: package.json — use ESM

Open package.json and add "type": "module". This tells Node to treat import / export as real ES modules.

package.json (excerpt)
{
  "name": "my-ts-agent",
  "type": "module",
  "dependencies": {
    "dotenv": "^17.4.2",
    "openai": "^6.39.1"
  },
  "devDependencies": {
    "@types/node": "^25.9.1",
    "ts-node": "^10.9.2",
    "typescript": "^6.0.3"
  }
}

Field by field

Only change what's shown — npm fills in other fields automatically.

Line 2Project name

Matches the folder you created. Used by npm if you publish (you won't here, but it's required).

Line 3"type": "module"

Without this, Node defaults to CommonJS (require). Our code uses import, so we need ESM. This one line prevents a whole class of "export not allowed" errors.

Why: Modern TypeScript + verbatimModuleSyntax expects your runtime module system to match your syntax.
Lines 4–7dependencies

Packages needed when the agent actually runs. Version numbers with ^ allow compatible updates when you reinstall later.

Lines 8–12devDependencies

Only needed while building and editing — not shipped to a server. TypeScript and type definitions live here.

Step 3: tsconfig.json

Replace the generated config with this. Two settings matter immediately: types: ["node"] and exactOptionalPropertyTypes.

tsconfig.json
{
  "compilerOptions": {
    "module": "nodenext",
    "target": "esnext",
    "types": ["node"],
    "strict": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "exactOptionalPropertyTypes": true,
    "noUncheckedIndexedAccess": true,
    "skipLibCheck": true,
    "sourceMap": true
  },
  "include": ["src/**/*"]
}

Compiler options explained

Each flag changes how TypeScript checks your code.

Lines 3–4module & target

nodenext matches how Node resolves ESM imports (including file extensions). esnext lets you use modern JavaScript features TypeScript will compile down as needed.

Line 5types: ["node"]

Tells TypeScript to load @types/node. If this is missing or set to [], fs, path, process, and crypto all show as unknown.

Why: This is the #1 fix when Node imports have red underlines after setup.
Line 6strict: true

Turns on all strict type-checking rules. Catches bugs early — worth the extra typing while learning.

Lines 7–8verbatimModuleSyntax & isolatedModules

verbatimModuleSyntax means import/export in TS must match what Node will see — no fake imports that disappear at compile time. isolatedModules ensures each file can compile on its own (required by many bundlers and runners).

Line 9exactOptionalPropertyTypes

Optional API fields can't be explicitly set to undefined — you must omit them entirely. This affects OpenAI SDK calls in Phase 2 where tools: undefined would error but leaving tools out is fine.

Lines 10–12Other safety nets

noUncheckedIndexedAccess — array/object lookups might be undefined. skipLibCheck — skip type-checking inside node_modules for speed. sourceMap — maps errors back to your TS line numbers when debugging.

Line 14include

Only files under src/ are part of this project. Create src/harness/ before adding TypeScript files there.

Step 4: Create the Session Class

Create src/harness/session.ts. This is the harness's memory — every message gets saved to disk immediately.

src/harness/session.tsDURABLE • JSONL
import fs from 'fs/promises';
import path from 'path';
import { randomUUID } from 'crypto';

export type Message = {
  role: 'user' | 'assistant' | 'tool' | 'system';
  content: string;
  timestamp: string;
  tool_call_id?: string;
  name?: string;
  [key: string]: any;
};

export class Session {
  public readonly id: string;
  private readonly filePath: string;
  public messages: Message[] = [];

  constructor(id?: string) {
    this.id = id ?? randomUUID();
    this.filePath = path.join(process.cwd(), 'sessions', `${this.id}.jsonl`);
  }

  async addMessage(role: Message['role'], content: string, meta: any = {}) {
    const msg: Message = {
      role,
      content,
      timestamp: new Date().toISOString(),
      ...meta,
    };

    this.messages.push(msg);

    await fs.mkdir(path.dirname(this.filePath), { recursive: true });
    await fs.appendFile(this.filePath, JSON.stringify(msg) + '\n');
  }

  async load() {
    try {
      const data = await fs.readFile(this.filePath, 'utf-8');
      this.messages = data
        .trim()
        .split('\n')
        .map((line: string) => JSON.parse(line));
    } catch (e) {
    }
  }

  getHistory() {
    return this.messages;
  }
}

Building session memory

Type this file section by section. Expand each block before writing those lines.

Line 1import fs from 'fs/promises'

Node's file-system module. The /promises version uses async/await instead of callbacks — easier to read when chaining disk writes.

Why: Sessions persist to disk; we need async file I/O.
Line 2import path from 'path'

Builds file paths correctly on macOS, Linux, and Windows (sessions/abc.jsonl vs sessions\\abc.jsonl).

Line 3import { randomUUID }

Generates a unique ID like a1b2c3d4-e5f6-... for new sessions. Built into Node — no extra package.

Why: Each conversation gets its own file; IDs must not collide.
Lines 5–12The Message type

Describes one entry in the conversation log:

  • role — who sent it: you, the model, a tool, or system instructions
  • content — the text (or tool result) itself
  • timestamp — when it was recorded (ISO string)
  • tool_call_id? / name? — optional fields for tool messages later
  • [key: string]: any — allows extra metadata without breaking the type
Why: TypeScript catches mistakes like passing role: 'human' before you run the agent.
Lines 14–17Class properties

id — public and read-only; safe to show in logs. filePath — private; callers shouldn't pick arbitrary paths. messages — in-memory copy of the conversation for fast access during a run.

Lines 19–22constructor

id ?? randomUUID() — use the passed-in ID when resuming a session, otherwise generate a new one. ?? only falls back on null/undefined, not empty strings.

path.join(process.cwd(), 'sessions', ...) — stores files in ./sessions/<id>.jsonl relative to where you run the agent.

Why: Durable path is decided once at construction — every message goes to the same file.
Line 24addMessage signature

async because writing to disk takes time. meta defaults to {} so callers can attach extra fields (like tool_call_id) without a separate parameter.

Lines 25–30Build the message object

Creates a plain object matching Message. new Date().toISOString() records exact time in UTC. ...meta spreads optional fields on top — later keys in meta can override earlier ones if you pass duplicates.

Line 32this.messages.push(msg)

Updates in-memory history immediately so the rest of the harness can read it without hitting disk again.

Lines 34–35Persist to disk

fs.mkdir(..., { recursive: true }) creates the sessions/ folder if missing — won't error if it already exists.

fs.appendFile adds one JSON line to the end of the file. Append-only means a crash mid-write only loses the last partial line, not the whole history.

Why JSONL: One JSON object per line. Easy to read, easy to append, easy to replay. This is your durable boundary.
Lines 38–46load() — resume a session

Reads the whole file, splits on newlines, parses each line back into a Message. Wrapped in try/catch: if the file doesn't exist yet (brand-new session), the catch runs and we leave messages as an empty array — that's intentional, not an error.

Why: After a restart, call load() before continuing so the agent remembers prior turns.
Lines 48–50getHistory()

Returns the messages array for the agent loop to send to the model. A method instead of reading .messages directly gives you a place to filter or transform history later (e.g. hide system snapshots from the UI).

Checkpoint: You now have durable memory. Before Phase 2, create the file, type it in, and run npm install if you haven't. No red squiggles on fs or process? You're ready.
